# Models

## Overview

`purge/Models` is Purge's domain-model package. It defines the value types the scanners, cleaners, uninstaller, Large Files, Duplicates, simulators, Scheduled Cleaning, and Everything else screens exchange: scanned rows, safety classifications, cleanup history and ledger records, project and command-line-tool catalogs, large-file and duplicate indexes, simulator descriptions, persisted scan snapshots, and the supporting geometry/claiming types those features share. Most declarations are `nonisolated` `struct`/`enum` value types so they can be built off the main actor; the exceptions are the AppKit appearance bridge (`AppearanceMode`/`AppAppearance`) and `SafetyLevel.color`, which is `@MainActor` because it reads `AppColors`.

Models describe and classify work; they do not decide deletion. Catalogs such as `ProjectArtifactCatalog`, `AppDotFolderCatalog`, and `CommandLineToolCatalog` only propose paths, and every proposal still passes through `DeletionSafetyPolicy`/`FileDeleter` outside this package. Persistence is expressed as `Codable` shapes and `UserDefaults`-backed stores; no file in this directory writes files, opens sockets, or starts processes.

## Invariants

**Safety classification and surfacing**

- `SafetyInfo.swift:SafetyLevel` has exactly three cases: `.safe` ("Safe to Clean"), `.medium` ("Check First"), and `.unknown` ("Not Sure"). Only `.safe` and `.medium` are risk tiers eligible for scan results; `.unknown` is a resolver fallback and is dropped at the scan-results assembly boundary. There is deliberately no "Do Not Delete" tier: dangerous paths are never allowlisted rather than classified.
- `SafetyInfo.swift:SafetyLevel.canSurfaceInScanResults` must remain `self == .safe || self == .medium`. Any new case must be treated as non-surfacing unless explicitly added here.
- `SafetyInfo.swift:SafetyLevel.sortOrder` is 0 for `.safe`, 1 for `.medium`, and 3 for `.unknown` (there is no 2). `displayName` and `symbolName(filled:)` cover every case, and `color` is `@MainActor` because it reads `AppColors`.
- `SafetyInfo.swift:SafetyInfo` is an immutable `Hashable` payload and is not `Codable`. Persisted rows must go through `LastScanSnapshot.swift:SavedSafety`; adding a field to one without the other silently loses it across launches.
- `CleanupExplanation.swift:SafetyInfo.fromExplanationDatabase` prioritizes an exact-path `UserOverridesStore` override, then the bundled explanation, then an explicit unknown result. The unknown path never becomes `.safe`.
- `CleanupExplanation.swift:SafetyInfo.forStaleProjectArtifact` defaults to the caller-supplied `level` (`.safe` by default), but an exact-path override wins outright; a non-nil `checkFirstReason` passes the result through `heldAtCheckFirst(path:)`, which raises `.safe` to `.medium` and leaves `.medium`/`.unknown` unchanged, again unless the exact path is overridden.
- `SafeFirstSelectAll.swift:SafeFirstSelectAll` is safe-first only when `filter == .all` and at least one entry is not safe. `toggled()` selects safe entries first and clears the selected list once all safe entries are selected; Check First rows are added only by `checkFirstLink` after every safe row is selected. `isEnabled` is false for an empty list, or for an All-filter list containing only unselected Check First rows.
- `CleanFailure.swift:CleanFailureReason` raw values are persisted in Cleanup History, so renaming a case turns old records into `.unknown`. `from(error:)` returns `nil` for file-not-found / already-gone errors, maps Cocoa and POSIX permission/volume/locking codes, then falls back to message checks, and returns `.unknown` otherwise. `resolved(from:path:fullDiskAccessGranted:)` may claim `.systemProtected` only after a permission error when Full Disk Access is already granted and `FileProtection.blocksRemoval` is true; it otherwise returns `.unknown`, never an invented cause.
- `CleanFailure.swift:FileProtection.blocksRemoval` checks the item and then the parent for immutability only. It deliberately does not test the parent for `com.apple.rootless`, because rootless directories can still release their contents.
- `CleanFailure.swift:CleanFailureItem.offersFinderRemoval` is true only for `route == .lockedUninstall` and reasons `needsAdministratorAccount`, `inUse`, `moveInFinder`, or `unknown`. All switches over `CleanFailureReason` (`explanation`, `systemImage`, `showsRetry`, `retryTitle`, `offersFinderRemoval`) must be updated together when a case is added.
- `CleanOutcome.swift:CleanOutcome.resolve` is precedence-ordered: no failures plus removals yields `.success`, no failures and no removals yields `.nothingLeft`, failures plus removals yields `.partial`, and failures with no removals yields `.skippedOnly` only when every failure is `.safetySkipped`, otherwise `.failed`. `showsFigure` is true only for `.success` and `.partial`.

**History and ledger persistence**

- `CleanupHistoryEntry.swift:CleanupHistoryEntry` has a hand-written `Codable` contract. Decoding requires `id`, `date`, `trigger`, and `deletedItems`; `bytesMovedToTrash` falls back to the legacy `totalFreedBytes` key and that legacy value must never become `bytesReclaimedOnVolume`; `bytesReclaimedOnVolume` stays optional (`nil` means unmeasured); `skippedItems` and `failedItems` default to empty; an unknown `kind` from a newer build decodes as `nil` instead of failing the entry. Encoding writes the current keys and omits `totalFreedBytes`.
- `CleanupHistoryEntry.swift:CleanupHistoryDeletedItemDTO.wentToTrash` honors an explicit `movedToTrash`; when absent, a path under `/Library/Developer/CoreSimulator/` is permanently deleted, otherwise `FileDeleter.removesDirectly` decides. Pre-#170 entries therefore remain readable with the right split.
- `CleanupHistoryEntry.swift:CleanupHistoryFailedItemDTO.failureReason` maps an unrecognized raw string to `.unknown`; `CleanupHistoryEntry.bytesReclaimedOnVolume` must render as unknown when `nil` and must never be substituted with moved bytes.
- `CleanupHistoryEntry.swift:CleanupHistoryFile` decodes entry-by-entry, skips entries it cannot read via its empty `SkippedEntry` decoder, and only stops if the list itself cannot advance. `append(_:maxEntries:)` inserts newest-first and trims to `maxEntries`; History must never lose the whole file because one entry is malformed.
- `CleanupLedger.swift:CleanupLedgerSession.id` is the same UUID as the matching `CleanupHistoryEntry` when both exist, which makes history import idempotent. `bytesReclaimedOnVolume` remains optional and unknown when `nil`; `bytesCleared` is exactly `bytesMovedToTrash + bytesRemovedDirectly`; `importedFromHistory` marks sessions reconstructed without row names or failure counts.
- `CleanupLedger.swift:CleanupLedgerBaseline.firstReleaseDate` is the 1.0 release bound (epoch `1_778_460_575`). `untrackedBytes` is `max(0, lifetimeMovedBytes - historyMovedBytes)`; `untrackedWindow` starts at `firstReleaseDate` or a plausible `firstSeenAt` and ends at the oldest history date; `untrackedBytes(inYear:calendar:)` splits a cross-year window by days and flags the share as an estimate.
- `CleanupLedger.swift:CleanupYearTotals.compute` is computed on demand and never stored. It filters sessions to the requested calendar year, de-duplicates by `id` across neighbouring-year files, sorts by date, counts manual/scheduled cleans, sums moved/direct/measured bytes and safety skips, buckets by source and month, keeps the biggest item/clean, records uninstalled app labels in removal order, and sorts labels by bytes descending then label. `bytesBeforeRecord` stays outside every item breakdown but is included in `headlineBytes`.

**Identity, ordering, and value semantics**

- `CacheItem.swift:CacheItem` stores `id` as `"def:<definitionKey>"` when grouped, otherwise `"path:<standardizedPath>"`, and stores `standardizedPaths` once at init to avoid repeated filesystem stats in SwiftUI bodies. `locations` must be non-empty because `path`, `bundleID`, and the id fallback index `locations[0]`. `withLocations(_:)` must preserve the row's id prefix and selection/safety state.
- `DevTool.swift:DevTool` id is `"dev:<definitionKey>:<sorted standardized paths joined by |>"`. Both initializers must build the same id, and the restoring initializer must use the saved standardized paths rather than re-stat the disk. `primaryOverridePath` is always the first declared path.
- `InstalledApp.swift:InstalledApp.id` is the standardized bundle path, deliberately not the bundle ID, so two installs that share a bundle ID (for example Xcode and Xcode-beta) remain distinct. `matchName` is kept separate from `name` so a display rename cannot loosen leftover matching.
- `UninstallItem.swift:UninstallItem.id` is the standardized path. A row with non-nil `keptForApp` starts unticked and is held back from deletion; `isTickedByHeader` excludes both kept rows and `homeFolderData` catalog folders. `UninstallAppPlan.toggleAllFromHeader` clears every non-kept row when all header rows are selected, otherwise selects only header-tickable rows.
- `UninstallItem.swift:UninstallPlan.uniqueSelectedItems` de-duplicates selected rows by id across apps, so shared bundle-ID leftovers are counted and trashed once. `permanentlyDeletedItems` contains only Homebrew cask bundles actually removed through Homebrew; everything else selected is a Trash move.
- `UninstallItem.swift:MatchReason.isHighConfidence` is true only for `.appBundle`, `.bundleID`, and `.groupID`; name/ledger/cross-evidence/catalog matches must stay unselected by default. Leftover sections follow `leftoverSectionRank` and must keep its one-section-per-reason ordering.
- `LargeFile.swift:LargeFile` stores `id` as the standardized path and builds `componentPaths` (default `[path]`, all standardized), `searchHaystack` (display name, raw parent path, source label, kind badge joined by newlines), and `locationLabel` once at init. `isFullyRemoved(byDeleting:)` requires every component path to be removed, so a multi-part AI model survives a partial delete. `matches(searchQuery:)` splits on whitespace and requires every term to match case- and diacritic-insensitively; an empty query matches everything.
- `LargeFile.swift:LargeFileCategoryFilter.activeRawValue` falls back to `all` when the selected duplicates or iCloud chip has no rows, or when a saved category is absent from the current rows. `duplicateSections` drops groups with fewer than two rendered members and matches a search against the whole group; `visibleIndices` uses the duplicates branch first, then the active filter.
- `DuplicateGroup.swift:DuplicateGroup` membership is by `LargeFile.id`, not by value. `reclaimableBytes` is `sizeBytes * (copyCount - 1)`, never `sizeBytes * copyCount`.
- `DuplicateGroup.swift:DuplicateIndex` groups are ordered by reclaimable bytes descending then digest id ascending; reverse maps are precomputed so a row never searches `groups`. `withDisplaySizes(from:)` restates each group to the smallest member's allocated size present in `files`; `removing(fileIDs:)` drops removed ids and any group left with fewer than two copies.
- `DuplicateKeeper.swift:DuplicateKeeper` only suggests a keeper. The sort key is deterministic from the path: location rank (0 real home, 1 Downloads/Desktop, 2 cache/temp), copy-name rank (0 canonical, 1 Finder/browser copy), fewer path components, then the path. The user must be able to override the suggestion.
- `AppSuiteGrouping.swift:AppSuiteGrouping.groups` groups only keys with at least two apps whose uppercased signing team IDs are all equal and non-nil; unsigned or mixed-team folders stay flat. `entries` includes every app exactly once and collapses a group only while at least two of its members are present. `partialSuites` counts only listed apps and never treats the uninstaller as one of the parts.
- `ProjectArtifactCatalog.swift:ProjectArtifactRule` is a proposal only: `matchesRoot` and `refusesArtifact` read the disk, but every candidate still passes `DeletionSafetyPolicy.isOfferedForCleanup`. `level` defaults to `.safe`; Terraform plugins and the Unity/Unreal artifacts are explicitly `.medium`. `ProjectArtifactCatalog.rules` is the single source of truth, with `rulesByKind` and `rulesByFolderName` derived from it.
- `CommandLineToolCatalog.swift:CommandLineToolCatalog.validate` requires non-empty names, plain `~/.` hidden home folders, no shared folders, no duplicates or nesting, shims directly inside `~/.local/bin`, kept paths outside the install folder, and no overlap with `AppDotFolderCatalog`. `load` returns `.empty` on a missing or invalid resource, so a bad catalog offers nothing.
- `AppDotFolderCatalog.swift:AppDotFolderCatalog.validate` requires bundle-ID-shaped non-Apple identifiers and exact `~/.` folders with no duplicates or containment. `entry(forFolderAt:home:)` matches only the exact standardized folder, never a parent or child. `load` returns `.empty` on failure.
- `LeftoverOwnerLedger.swift:LeftoverOwnerLedger` matches bundle IDs case-insensitively, updates display name/date and appends new folders on re-record, prunes folders that no longer exist (and entries left empty), and versions the file with `currentVersion = 1`. Whether an app is still installed is decided at scan time, never stored.
- `EverythingElseGroup.swift:EverythingElseGroup.allCases` defines claim order. The first eight cases (`otherApps` through `otherUsers`) are measured; `trash`, `macOS`, and `systemData` are display-only and claim no bytes. `EverythingElseBucket.groups` follows the same `allCases` order within each bucket.
- `EverythingElseMeasurement.swift:EverythingElseBreakdown` claims in `EverythingElseGroup.measured` order after the five Overview categories, processes child folders before whole roots, caps group totals in claim order to `everythingElseBytes`, then caps macOS and Trash to what remains, and sets `isApproximate` whenever anything was capped or a recorded figure is present. `systemDataBytes` is the non-negative remainder after measured groups, macOS, and Trash, so the page adds up to the Overview figure without double counting.
- `OverviewBreakdown.swift:OverviewBreakdown` clamps total/free to non-negative values, derives `usedBytes = totalBytes - freeBytes`, claims live sources in `OverviewCategory.allCases` order, and lets recorded totals fill only the unsorted remainder. `share(of:)` is clamped to 0...1 and returns 0 for a zero total.
- `OverviewBreakdown.swift:ClaimedPaths.claim` returns 0 for an empty path, an already-covered path, or a descendant of an already-claimed folder; otherwise it adds `max(0, bytes - bytes already claimed under the folder)`. Claim ordering is therefore part of correctness: earlier categories own overlapping bytes.
- `TreemapLayout.swift:TreemapLayout` drops zero/negative weights, returns no tiles for a zero-area rect, and never hides the `TreemapPlan.smallerID` tile; non-smaller tiles thinner than `minimumTileSide` are omitted and counted in `hiddenCount`. `plan` puts previously seen ids first in their prior order, then new ids by descending weight, and records that order for the next re-measure.
- `ExcludedPathsTotal.swift:ExcludedPathsTotal.topLevel` drops any path that sits inside another listed path; `compute` adds measured values, ignores missing paths, marks unmeasurable paths as `hasUnmeasured`, and marks any path without a result as `isComplete == false`. An unmeasurable path must never count as zero.
- `SimulatorRuntime.swift:SimulatorRuntime.parseRuntimeList` accepts only entries whose `deletable` flag is true, requires runtime identifier/version/build and a non-empty location, defaults missing size to 0, skips legacy images held by an Apple download, and sorts by platform ascending then version numerically descending. `safetyInfo` and `SimulatorDevice.safetyInfo`/`runningSafetyInfo` always return `.medium` (Check First) because `simctl` deletion is permanent.
- `SimulatorRuntime.swift:SimulatorRuntime.isHeldByAppleDownload` returns true for a legacy image when the build or download set is unknown, and otherwise compares builds case-insensitively after trimming. `xcodeRuntimeBuilds` returns `nil` when it found no chosen build, never an empty set that would mark Xcode's own runtime safe.
- `SimulatorDeviceList.swift:SimulatorDeviceList` treats a runtime as unreadable when its value is not an array or an entry cannot be decoded; unreadable runtimes are not offered. `contains(udid:)` searches every runtime, unreadable ones included, so a device is never presumed gone.
- `LastScanSnapshot.swift:LastScanSnapshot` is versioned with `currentVersion = 1` and is valid only when `appBuild` equals the running bundle's `CFBundleVersion`. A row may be written only when `isWritable(_:home:)` is true (outside protected locations and readable by a limited scan, following links), and every saved row is display-only: no selection, clean, menu-bar count, or scheduled clean may read it. Restored rows always start unselected, and `SavedInstalledApp.restored` always starts not running.
- `LastScanSnapshot.swift:LastScanSnapshot.removeRows` removes matching cache locations and drops empty cache rows, removes whole dev-tool rows when any path matches, removes simulator/runtime/app/leftover rows by their URL, and removes project roots or individual artifacts while dropping empty groups.
- `AppearanceMode.swift:AppearanceMode.current` reads `UserDefaults.standard` key `appearance.mode` and falls back to `.system` for a missing or unrecognized raw value. `nsAppearance` is `nil` for system, `.aqua` for light, and `.darkAqua` for dark. `resolvedColorScheme` for `.system` reads `NSApplication.shared.effectiveAppearance`, not `NSApp`, so it is safe while `PurgeApp` state initializes.
- `ScheduledCleaningPreferences.swift:DevToolsStalenessOption.currentThresholdDays` must check that the key exists before calling `integer(forKey:)`; a missing key would otherwise read as 0, which is `showAll`. Missing returns the `.sixMonths` default (180), an explicit 0 stays Show all, and any other unrecognized value returns the default.
- `ScanRecord.swift:ScanRecord.removeLargeFiles` decrements count and bytes with a floor of 0 and drops categories left with zero count; it does nothing when `largeFileCategories` is nil. `ScanRecordStore` keys are `overview.scanRecord.<OverviewCategory.rawValue>`, and a decode failure reads as `nil`, never a crash.
- `LargeFile.swift:LargeFileFilterDefaults.register` migrates the legacy `largeFiles.minSizeMB` value only when the new size key is absent and the legacy value maps to a known threshold, then registers both current defaults. `removeLegacyCategory` removes `filter.largeFiles`; the category chip itself is not persisted.
- `ScanQueue.swift:ScanQueueState` allows exactly one active step. `enqueue` skips the active step and duplicates; `prioritize` moves steps to the front preserving their relative order, skips the active step unless `requeueingActive` is true, and de-duplicates; `startNext` removes the first pending step; `finishActive` clears only the active slot. `isRunningCategoryScan` deliberately ignores `everythingElse`.
- `ScanQueue.swift:LaunchScanPlan.steps` includes `ScanStep.allCases` that are not `runsOnlyOnDemand`, were not loaded this session, and either need no Full Disk Access or have it. The Everything else and command-line-tool steps never run at launch or from Scan Everything.
- `AppFolderSummary.swift:AppFolderSummary.make` assigns each app path to the longest matching root, emits every root with apps plus every added folder (even unavailable/empty), and marks `isAvailable` from the current roots list. `isWorthShowing` is true only for an added folder or a drive folder with apps, so an ordinary built-in-only Mac keeps the plain header.
- Enum exhaustiveness is a contract: switches over `SafetyLevel`, `EverythingElseGroup`, `EverythingElseBucket`, `CleanUpSource`, `ScanStep`, `OverviewCategory`, `UninstallCategory`, `MatchReason`, `LargeFileCategory`, `LargeFileKind`, `DeletableArtifactKind`, `ProjectType`, and `CleanFailureReason` must be extended when cases are added. `allCases` order is behavioral for `OverviewCategory` (byte claim order), `EverythingElseGroup` (claim order), `EverythingElseBucket` (page order), and `ScanStep` (launch order).
- The models are value types: copying a row and mutating `isSelected`, `safetyInfo`, `sizeBytes`, or plan state must not affect other rows. Identity is carried by explicit `id` strings or UUIDs, and plans key state by those ids rather than by object reference.

## Side Effects

- `AppearanceMode.swift:AppearanceMode.current` reads `UserDefaults.standard` key `appearance.mode`; `Appacency` has no write path in this file. `AppearanceMode.resolvedColorScheme` reads `NSApplication.shared.effectiveAppearance`, and `nsAppearance` constructs `NSAppearance(named:)`.
- `AppearanceMode.swift:AppAppearance.apply` mutates `NSApp.appearance` and sets `appearance`, `needsLayout`, `needsDisplay`, and `displayIfNeeded` on every `NSApp.windows` window. `AppAppearance.addSystemThemeObserver` registers an observer on `DistributedNotificationCenter.default()` for `AppleInterfaceThemeChangedNotification` (main queue) and returns the token the caller must remove.
- `ScheduledCleaningPreferences.swift:DevToolsStalenessOption.currentThresholdDays` only reads `UserDefaults`; it does not write the default back.
- `LargeFile.swift:LargeFileSizeThreshold.current`, `LargeFileAgeThreshold.current`, `LargeFileFilterSnapshot.current`, and `LargeFileAgeThreshold.currentThresholdDays` read `UserDefaults`. `LargeFileFilterDefaults.register` may write the migrated size key and registers defaults; `LargeFileFilterDefaults.removeLegacyCategory` removes the legacy category key. All accept an injected `UserDefaults` for tests.
- `ScanRecord.swift:ScanRecordStore.record(for:)` and `allRecords()` decode JSON from `UserDefaults`; `save(_:for:)` encodes JSON and writes it under the category key. Encoding failures are swallowed rather than thrown.
- `AppDotFolderCatalog.swift:AppDotFolderCatalog.load` and `CommandLineToolCatalog.swift:CommandLineToolCatalog.load` read bundled JSON resources with `Data(contentsOf:)`; their `shared` constants perform that load on first access. Missing or invalid data yields an empty catalog, not an error.
- `SimulatorRuntime.swift:SimulatorRuntime.downloads(in:)` reads `/System/Library/AssetsV2` directory entries and each asset's `Info.plist`; a missing root returns an empty array, while an unreadable platform folder or plist returns `nil` ("unknown"). `parseRuntimeList`, `deviceCounts`, `xcodeRuntimeBuilds`, `deviceReachByBuild`, `SimulatorDeviceList.parse`, and `SteamGame.parse` are pure JSON/text parsers.
- `ProjectModels.swift:NodePackageManager.detect(in:)` checks for `pnpm-lock.yaml`, `yarn.lock`, `package-lock.json`, and `npm-shrinkwrap.json` with `FileManager`. `ProjectArtifactCatalog.swift:ProjectArtifactRule.matchesRoot`/`refusesArtifact` list the project root and check marker/refusal files. These are reads only; the catalog never deletes.
- `AppFolderSummary.swift:AppFolderPaths.read` calls `AppFolders.builtInRoots`, `roots`, and `pickedFolders`, and reads `volumeLocalizedName` for non-built-in, non-added roots. `AppFolderListing.swift:AppFolderListing.load` does the same plus `AppFolders.driveRoots`, and must run off the main thread because it lists volumes and asks drives about their filesystem.
- `CleanFailure.swift:FileProtection.isImmutable` reads `isUserImmutable`/`isSystemImmutable` resource values; `isRootlessProtected` calls `getxattr(..., "com.apple.rootless", ...)`; `blocksRemoval` does both for the item and its parent. `CleanFailureReason.resolved` invokes that probe only for a permission error after Full Disk Access is granted.
- `CleanupExplanation.swift:SafetyInfo.fromExplanationDatabase` reads `UserOverridesStore` for the exact path and the bundled `ExplanationDatabase`; `heldAtCheckFirst` reads the override store. `SafetyInfo.forStaleProjectArtifact` delegates to both.
- `LastScanSnapshot.swift:LastScanSnapshot.isWritable` walks protected locations and follows links with `readlink`-style resolution; its documentation requires calling it off the main thread. The snapshot type itself does not write the file from this package.
- `CacheItem.swift:CacheItem.init`, `DevTool.swift:DevTool.init`, and `LargeFile.swift:LargeFile.init` call `standardizedFileURL`, which the code comments identify as a filesystem stat; that is why ids and standardized paths are cached. `UninstallItem.id` standardizes on each access. `OverviewSizedItem.normalized` is string-only and never stats.
- `SafetyInfo.swift:SafetyLevel.color` is `@MainActor` and reads Theme tokens (`AppColors.statusSafeText`, `statusCheckText`, `statusUnsureText`); call it only from view bodies.
- No model performs network access, starts a process, or writes a user file. The only writes here are the `UserDefaults` paths listed above; process execution and deletion belong to `FileDeleter`, `ProcessRunner`, and the root helper outside this package.
